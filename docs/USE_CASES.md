# Use Cases (Install-and-Run Product)

작성일: 2026-02-25  
버전: v1.1.0  

## 1) UC-01: 신규 사용자 1회 설치 후 즉시 실행
- ID: UC-01
- Actor: 첫 사용자(블록체인 지식 제한)
- 목표: 설치 후 5분 내 노드 상태 확인
- 전제: 설치 매체(Windows/macOS/Linux/Docker)만 보유

### 정상 흐름
1. 설치 실행 파일 실행
2. `설치 시작` 클릭
3. 동의/라이센스 확인 후 `다음`
4. 기본 포트/경로에서 `다음`
5. `완료` 및 `지금 실행` 체크
6. 초기 온보딩에서 `시작` 클릭
7. `상태 새로고침`으로 `is_running=true` 확인
8. `API 상태 확인`을 통해 `/status` 응답 확인

### 예외
- 포트 충돌: `포트 변경 제안` 버튼으로 대체 포트 선택
- 데이터 경로 쓰기 실패: 경고 후 기본 경로로 복귀
- 네트워크 미연결: 오프라인 알림 + 재시도 가이드

### 결과
- 첫 실행 성공 시 1회성 환영 대시보드 표출
- 운영자에게 로그/토큰 접근 방법 제시

## 2) UC-02: 데모/개발 환경에서 빠른 노드 실행
- ID: UC-02
- Actor: 개발자
- 목표: 추가 설정 없이 `run` 동작으로 간단 테스트

### 정상 흐름
1. 설치 후 `CLI 실행` 진입
2. `eastsea run` 또는 버튼형 대체 경로 `빠른 시작` 실행
3. 기본 네트워크 참여 토폴로지 확인
4. `getBlockHeight`, `sendTransaction` API 테스트

### 예외
- API 토큰 미설정: 토큰 생성 화면으로 전환
- API 오류: 에러코드와 샘플 요청 템플릿 제공

## 3) UC-03: 운영자 노드 재시작/정지 요구
- ID: UC-03
- Actor: 운영자
- 목표: 서비스 점검을 위해 중단/재시작

### 정상 흐름
1. 대시보드 진입
2. `중지` 클릭
3. 상태가 `Stopped`로 바뀜을 확인
4. 유지보수 완료 후 `재시작` 클릭
5. 상태 `Running` 전환 확인

### 예외
- 중지 타임아웃: `강제 중지` 버튼 노출 후 복구 가이드
- 재시작 실패: 자동 롤백/재시도 및 로그 표시

## 4) UC-04: 배포 중 업데이트 적용
- ID: UC-04
- Actor: 플랫폼 운영자
- 목표: 운영 중단 최소화 업데이트 적용

### 정상 흐름
1. `업데이트 확인` 클릭
2. 릴리즈 노트 확인
3. `다운로드/적용` 클릭
4. 업데이트 진행 및 체크섬 검증
5. 자동 재시작 후 상태 확인

### 예외
- checksum 불일치: 실패 알림 + `롤백` 노출
- 중간 실패: 이전 버전으로 자동 복귀

## 5) UC-05: 업데이트 실패 복구
- ID: UC-05
- Actor: 운영자
- 목표: 실패 시 사용자 데이터 보존

### 정상 흐름
1. 업데이트 중간 중단 발생
2. 복구 알림에서 `롤백` 클릭
3. 실행 버전 원복 후 운영 상태 확인
4. `진단 레포트` 열람

### 예외
- 롤백 실패: 안전 모드로 진입, 수동 롤백 가이드 자동 노출

## 6) UC-06: 포트/권한 오류로 즉시 실행 실패 해결
- ID: UC-06
- Actor: 시스템 관리자
- 목표: 첫 실행 실패를 셀프 해결

### 정상 흐름
1. `시작` 클릭 시 에러 알림
2. 원인 코드 확인(`ERR-PORT-CONFLICT`, `ERR-PERMISSION`)
3. `문제 수정` 버튼으로 진단 가이드 이동
4. 포트 수정 또는 권한 승인
5. `재시작` 버튼으로 재실행

### 예외
- 권한 승인 거절: `수동 설치 가이드` 링크 제공

## 7) UC-07: 데이터 손상 의심 시 복구
- ID: UC-07
- Actor: 운영자
- 목표: 노드 데이터 정합성 검증 및 복구

### 정상 흐름
1. `데이터 상태 점검` 메뉴 진입
2. `백업 생성` 클릭
3. 손상 의심 블록/트랜잭션 재검증
4. 필요시 `복구 실행`

### 예외
- 복구 실패: 운영 모드 진입 유지 + 원본 백업 안내

## 8) UC-08: 로그 기반 장애 대응
- ID: UC-08
- Actor: 운영/Support
- 목표: 장애 원인 추적 후 조치 완료

### 정상 흐름
1. 대시보드에서 `로그 보기` 클릭
2. 오류 레벨 `ERROR` 필터 적용
3. 해당 오류의 재현 버튼 혹은 연관 버튼(`재시작`, `중지`) 선택
4. `지원 티켓 생성`으로 장애 데이터 수집

### 예외
- 로그 접근 실패: 로그 파일 권한/경로 가이드 제공

## 9) UC-09: 보안 토큰 갱신
- ID: UC-09
- Actor: 보안 관리자
- 목표: 오래된 토큰을 안전하게 교체

### 정상 흐름
1. `토큰 재생성` 클릭
2. 기존 토큰 비활성화 확인
3. 신규 토큰 복사/안전 저장
4. `권한 테스트` 수행

### 예외
- 저장 실패: 클립보드 접근 가이드, 오프라인 임시저장 경고

## 10) UC-10: 노드 삭제 및 재설치
- ID: UC-10
- Actor: 고급 사용자
- 목표: 깨끗한 재설치

### 정상 흐름
1. 설정 메뉴에서 `제거` 클릭
2. `설정/로그 삭제` 또는 `데이터 보존` 선택
3. 재설치 실행
4. 온보딩 마법사 재진입

### 예외
- 제거 중 프로세스 잔존: 강제 종료 후 재시도

## 11) UC-11: 멀티 노드 동시 참여(3개 노드 이상)
- ID: UC-11
- Actor: 실험 네트워크 운영자
- 목표: 노드 간 P2P 연결 검증

### 정상 흐름
1. 첫 노드 실행 후 `지금 실행`
2. 두 번째/세 번째 노드에서 첫 노드 주소 지정
3. 각 노드의 `피어 추가` 버튼 사용
4. `네트워크 상태`에서 peer_count 증가 확인

### 예외
- 핸드셰이크 실패: MTU/포트/방화벽 원인 분류

## 12) UC-12: 지원 포털 요청 대응(버튼 기반)
- ID: UC-12
- Actor: 신입 운영자
- 목표: 사용 중 문제를 셀프 서포트

### 정상 흐름
1. `도움말` → `문제 진단`
2. `진단 실행` 클릭
3. 로그·설정·버전 정보를 묶어 복사
4. `지원 문의` 버튼으로 전달

### 예외
- 네트워크 미제공: 오프라인 텍스트 템플릿 제공
