# Product Specification v1.1 (Install-and-Run as Primary Goal)

## 1) 문서 정보
- 문서명: Product Specification
- 버전: 1.1.0
- 작성일: 2026-02-25
- 상태: Productization Draft (Install-First)
- 핵심 목표: `아무 플랫폼에서나 설치 후 즉시 실행`

## 2) 최종 목표 정의
- 최종 사용자 입장에서 Transmission처럼 설치만 하고 바로 서비스가 가동되는 상태를 기본값으로 둔다.
- “개발 환경/옵션 설정/운영 지식”이 없어도 실행 가능한 **Zero-Setup Start**를 목표로 한다.
- 장기적으로는 데스크톱/서버/컨테이너가 동일한 체험으로 동작하는 통합 배포 체계를 완성한다.

## 3) 제품 개요
- 제품명: **Eastsea Node (v1)**
- 형태: 크로스 플랫폼 실행형 플랫폼 서비스 (RPC + 노드 상태/운영 제어 기능)
- 기본 사용자: 일반 운영자, 파트너사 연동 팀, 내부 QA

## 4) 핵심 가치 제안
- 설치 난이도 최소화: 별도 빌드/컴파일/DB 초기화 불필요
- 첫 실행 성공률 극대화: 기본 설정 내장 + 자동 초기화(wizard)
- 운영 일관성: 어떤 플랫폼에서 실행해도 동일한 동작, 동일한 API 버전
- 장애 복구 용이성: 설치+업데이트+롤백 동선 통합

## 5) 성공 지표 (KPI)
### 제품 목표
- 신규 설치 후 첫 5분 내 기본 서비스 준비 완료율: >= 95%
- 첫 실행 성공률: >= 99% (공개 플랫폼에서의 설치/실행 테스트)
- 기본 사용 시나리오 실행 횟수: 플랫폼별 월간 10건 이상
- 설치 문의 티켓(오류로 인한) 감소율: 1개월 이내 50% 감소

### 기술 목표
- 지원 플랫폼 1회 릴리즈 기준 최소 95% 동일 동작
- 핵심 API 응답 P95: <= 500ms
- 업타임: 99.5% (초기 v1)
- 배포 롤백 시간: 10분 이내

## 6) 플랫폼 지원 범위(설치 우선)
- 데스크톱/서버
  - Windows 10/11 x64 (`.msi` 또는 `.exe`)
  - macOS 12+ (Apple Silicon + Intel, `.dmg`)
  - Linux x86_64 (`.deb`, `.rpm`, `.AppImage`)
- 서버/클라우드
  - Docker (single-command run)
  - Docker Compose(옵션)
- 개발자
  - CLI Installer (`curl` + 셸 스크립트)
- 향후 v2
  - iOS/Android는 범위 밖, Web Desktop wrapper는 기술 검토 후

## 7) 사용자 여정(Zero-Setup)
1. 설치 마법사/패키지 실행
2. 첫 실행 시 필수 검사(포트/권한/저장 위치)
3. 기본 사용자/보안 설정 생성(필수 최소값)
4. 자동 데이터 초기화(스키마 자동 마이그레이션)
5. 상태 페이지/관리 화면 노출
6. 기본 연동 엔드포인트 동작 안내

## 8) 수용 기준
### 제품 릴리즈 수락 조건
- 각 지원 플랫폼에서 설치→실행→상태 확인→기본 API 호출이 성공해야 함.
- 기본 시나리오(설치/시작/상태조회/중지/재시작) 100% 자동화 테스트 통과.
- 설치 중 인터셉트 없이 기본 보안 설정이 적용되어야 함.

## 9) 기능 요구사항
요구사항 ID는 `REQ-###`.

### 9.1 설치/실행 체계 (Installability, P0)
- **REQ-100 (P0)**: 지원 플랫폼별 설치 패키지가 제공되어야 하며, 설치 후 즉시 실행 가능한 실행 파일/서비스가 생성돼야 한다.
  - AC:
    - Windows/macOS/Linux에서 1회 설치 후 서비스 시작 가능
    - 기본 데이터 디렉터리 자동 생성
- **REQ-101 (P0)**: 첫 실행에서 기본 설정 마법사(초기 사용자 계정/포트/데이터 경로) 제공.
  - AC:
    - 기본값으로 즉시 실행 가능
    - 사용자가 변경 시 유효성 검증 후 저장
- **REQ-102 (P0)**: 플랫폼별 설치/업데이트/제거(언인스톨) 동작 일관성 보장.
  - AC:
    - 업데이트/다운그레이드 동선 존재
    - 제거 후 잔존 설정/데이터 처리 옵션 표시
- **REQ-103 (P1)**: CLI 설치 스크립트 제공으로 Linux/CI 환경에서 자동 설치 가능.
- **REQ-104 (P1)**: Docker 이미지에서 볼륨 마운트 기반 즉시 실행 가능해야 함.

### 9.2 런타임 안정성 (Runtime, P0)
- **REQ-110 (P0)**: 처음 실행 시 내장 기본값 기반으로 영속성 저장소를 초기화/부팅해야 한다.
- **REQ-111 (P1)**: 포트/권한 충돌 자동 탐지 및 대체 포트 제안.
- **REQ-112 (P2)**: 설치 직후 하드웨어/OS 진단 결과를 표시하는 헬스 리포트 제공.

### 9.3 운영/관리 (P1)
- **REQ-120 (P0)**: 실행 중 자동 업데이트 유닛(체크/다운로드/적용) 또는 수동 확인 기능 제공.
- **REQ-121 (P1)**: 단일 버튼 재시작/중지/서비스 재등록 UI/CLI 지원.
- **REQ-122 (P2)**: 백그라운드 실행 상태(트레이/메뉴 바) 지원.

### 9.4 기존 핵심 API·보안 요구사항(제품화)
- **REQ-001 (P0)**: 토큰 기반 인증.
- **REQ-002 (P1)**: 역할 기반 권한 정책.
- **REQ-010 (P0)**: 상태/설정 영속성 보존.
- **REQ-021 (P0)**: `server.zig`에서 mock 응답 제거 및 실제 실행 데이터 사용.
- **REQ-040 (P0)**: TLS/비밀 외부 주입.
- **REQ-050 (P0)**: CI/CD 게이트 통과 후 배포.

## 10) 비기능 요구사항
- 사용성: 설치 실패 메시지가 정확하고 가이드 가능해야 함.
- 신뢰성: 재시작 후 데이터 정합성 보존.
- 보안: 기본 권한 최소화, 키/비밀 외부 주입
- 접근성: 기본 화면/CLI 명령은 초심자에게 친화적 문구 제공

## 11) 배포/배포물 구조
- 산출물
  - Windows Installer
  - macOS Installer
  - Linux DEB/RPM/AppImage
  - Docker Image
  - 설치 스크립트
- 업데이트 채널
  - release manifest + 체크섬 + 릴리즈 노트
- 설치/설정 파일
  - 기본 설정은 플랫폼별 표준 위치
  - 사용자 설정은 덮어쓰기 방지 및 백업 포함

## 12) 데이터 및 마이그레이션
- 버전 업그레이드시 스키마 마이그레이션 자동 수행
- 마이그레이션 실패 시 안전 모드로 롤백 또는 수동 복구 안내
- 데이터 백업은 설치 및 업데이트 전 자동 생성(옵션 기본 ON)

## 13) 품질 게이트
- 설치 패키지 별 smoke test 통과(Install -> start -> stop)
- 각 플랫폼별 릴리즈 아티팩트 무결성 검사
- P0 요구사항이 누락되면 릴리즈 금지

## 14) 출시 범위 (v1)
- In Scope
  - 멀티 플랫폼 설치 패키지
  - Docker 단일 실행
  - 기본 운영 대시보드/상태 확인 API
  - 자동 업데이트/롤백 경로
- Out of Scope (v1)
  - 다중 테넌트 관리 UI 고도화
  - 모바일 앱/브라우저 확장 설치형 UX

## 15) 위험 및 대응
- 플랫폼별 패키저 의존성 리스크(서명/권한)
  - 대응: 검증된 패키징 도구 기반 자동화
- 업데이트 실패로 인한 서비스 중단
  - 대응: 단계적 배포 + 롤백 자동화
- 초보 사용자 설정 오류
  - 대응: 안내 중심 온보딩 + 진단 모드

## 16) 운영 변경관리
- 변경 요청은 플랫폼별 영향도 필수 명시(Windows/macOS/Linux/Docker)
- installer/배포 스크립트 변경 시 패키지 버전과 API 버전 동시 상승

## 17) 실행 전환 문구
- 본 스펙은 이후 문서(`REQ_MATRIX`, `ROADMAP`, `IMPLEMENTATION_PLAN`)를 설치 중심으로 정렬한다.
- 다음 단계: 요구사항 ID를 플랫폼(Windows/macOS/Linux/Docker)별로 분해해 릴리즈 후보 체크리스트로 연결.
