## 0) 전제
- 기존 문서: `PRODUCT_SPEC`, `REQ_MATRIX`, `ROADMAP`, `IMPLEMENTATION_PLAN`
- 기준 산출물:
  - `UNIT_TEST_PLAN.md`
  - `TEST_CASES.md`
  - `USE_CASES.md`
  - `TOTAL_USER_EXPERIENCE_MAP.md`

## 1) 순차 단계 1: 준비+기반 구축
### 목표
- 버튼 액션 ID 사전 정의
- P0 유닛 테스트 뼈대 생성
- 설치 실패 패턴 1차 진단

### 산출물
- `button-action-catalog`(버튼명↔핸들러 매핑표)
- 테스트 데이터/fixture
- 환경 체크 자동화 스크립트(포트/권한/경로)

### 완료 조건
- `REQ-100`, `REQ-101`, `REQ-110` 유닛 커버리지 80% 달성
- 설치 화면 1회 클릭 플로우 문서와 테스트 케이스 일치

## 2) 순차 단계 2: P0 동작 잠금
### 목표
- 설치/온보딩/기본 제어 버튼 유닛+통합 테스트 완료

### 산출물
- `UT-100~110`, `TC-INSTALL-*`, `TC-RUN-*` 실행 결과
- P0 장애 시나리오 대응 스니펫(포트, 권한, 경로)

### 완료 조건
- install→start→/status→stop 통합 smoke 통과
- P0 UI 버튼 단위 실패율 0%

## 3) 순차 단계 3: 운영성 고도화
### 목표
- 업데이트/롤백 및 서비스 제어 버튼 안정화

### 산출물
- `UT-120`, `TC-UPDATE-*`, `UC-04`, `UC-05`
- 재시작 큐/중복 호출 보호 테스트

### 완료 조건
- 실패 업데이트 1건당 롤백 성공률 100%
- `시작/중지/재시작` 버튼 경합 테스트 통과

## 4) 순차 단계 4: 서비스 운영 확정
### 목표
- 인증/보안/데이터 복구 유닛과 케이스 정리

### 산출물
- `UT-001`, `UT-002`, `UT-010` 완료
- `TC-SEC-*`, `TC-UNINSTALL-*`, `TC-ONEFLOW-*`
- 유즈케이스 기반 장애 대응 가이드 매핑

### 완료 조건
- 주요 API 유닛/통합 케이스 통과율 90% 이상
- 설치 후 1시간 내 첫 상태 조회율 95% 유지

## 5) 순차 단계 5: 총체적 UX 및 문서 동기화
### 목표
- 전체 사용자 여정 기반 사용성 정렬

### 산출물
- `TOTAL_USER_EXPERIENCE_MAP` 업데이트 반영한 UI 텍스트
- 에러 가이드 copy 통합
- `USE_CASES`와 `TEST_CASES` 교차 링크

### 완료 조건
- 신규 사용자 5분 시나리오 통과율 80% 이상(내부 사전교육 대상)
- 사용성 실패 지점 5개 이하

## 6) 순차 단계 6: 출시 후보
### 목표
- 전 항목 문서·테스트 증빙 정합성과 릴리즈 게이트 통과

### 산출물
- P0 우선순위 테스트 리포트
- `Go/No-Go` 체크리스트
- 설치형 사용 가이드 최종본

### 완료 조건
- P0 누락 없음
- 플랫폼별 install → run → status → stop 성공률 동일 기준 통과
- 업데이트/롤백 데모 1회 이상 완료

## 7) 실무 운영 루프(릴리즈 이후)
- 운영 반복:
  - 실패 케이스 Top 10 갱신
  - 버튼 액션별 실패 로그 분석
- 순환 갱신:
  - Use case 갱신 (새 OS/플랫폼 패치 반영)
  - UX map 감정지수 업데이트(응답시간/오류빈도/재시도율)
- 각 릴리즈 주기마다:
  - 각 버튼의 실패 메시지를 표준 코드와 함께 재검증
  - 자동 업데이트 및 롤백 정합성 드라이런
