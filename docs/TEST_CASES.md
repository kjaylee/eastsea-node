# Test Cases (Button-Granularity, Install-and-Run)

작성일: 2026-02-25  
버전: v1.1.0  
기준: `UT` 기반 + `REQ Matrix` 기반으로 실제 사용자/운영자 조작을 1개 버튼 단위까지 분해

## 1) 테스트 계층
- UI/CLI 기능은 버튼(또는 CLI 동등 명령) 단위로 케이스를 만든다.
- 우선순위: P0 > P1 > P2.
- 각 케이스는 실행 전/중/후 상태를 반드시 기록한다.
- 실패 시 표준 메시지 코드 + 대응 체크리스트를 같이 확인한다.

## 2) 테스트 케이스 표기법
- ID 형식: `TC-<도메인>-<번호>`
- P: P0, W: P1, T: P2
- 상태: N(정상), E(오류), R(복구)
- 채널: `UI`, `CLI`, `API`

## 3) 설치/온보딩 (P0, W)

### TC-INSTALL-001 [P][UI]
- 제목: 설치 시작
- 사전 조건: 새 디바이스 또는 기존 설치 흔적 없음
- 버튼: `설치 시작`
- 절차:
  1. 실행 파일(또는 패키지)을 실행한다.
  2. 설치 마법사의 첫 화면에서 `설치 시작` 클릭.
  3. 동의 체크박스 선택 후 다음 단계로 진행.
- 기대 결과:
  1. 환경 점검 단계로 전환된다.
  2. 최소 사양/권한 경고가 없다면 기본 경로가 노출된다.
  3. 30초 내 상태 바가 `확인 중`에서 `진행 가능`으로 변한다.
- 통과 기준: 단계 전환 실패/알 수 없는 경고 0건.

### TC-INSTALL-002 [P][UI]
- 제목: 설치 경로 변경 + 저장 권한 오류 처리
- 사전 조건: 쓰기 권한이 제한된 경로 존재
- 버튼: `찾아보기`, `다음`
- 절차:
  1. `찾아보기`로 권한이 없는 경로를 선택.
  2. `다음` 클릭.
- 기대 결과:
  1. 즉시 오류 표시(권한 부족 코드: `ERR-PATH-WRITE`).
  2. `설치 경로 재선택` 버튼이 활성화.
  3. 기존 기본 경로로 복귀 가능.

### TC-INSTALL-003 [P][UI]
- 제목: 포트 충돌 자동 처리
- 사전 조건: 기본 포트 `8000`, `8545` 점유 상태
- 버튼: `다음`, `포트 자동 변경`
- 절차:
  1. 기본값으로 계속 진행.
  2. 충돌 알림이 뜨면 `포트 자동 변경` 클릭.
  3. 변경된 포트로 최종 확인 후 `다음`.
- 기대 결과:
  1. 대체 포트 2개 이상 제안.
  2. 사용자가 제안 포트를 선택하면 검사 성공.
  3. 메시지에 제안 이유가 남는다.

### TC-INSTALL-004 [P][UI]
- 제목: 관리자 계정 초기값 생성
- 사전 조건: 온보딩 단계
- 버튼: `기본값 사용`, `고급 설정`
- 절차:
  1. `기본값 사용` 클릭 후 진행.
  2. `고급 설정`에서 사용자명/비밀번호 수동 입력 후 유효성 검사.
- 기대 결과:
  1. 기본값은 강도 기준 충족.
  2. 약한 비밀번호 입력 시 비활성화와 조언 문구 표시.

### TC-INSTALL-005 [W][UI]
- 제목: 설치 완료 후 바로 실행 체크
- 사전 조건: 설치 마법사 완료
- 버튼: `완료`, `지금 실행`
- 절차:
  1. 마지막 화면에서 `완료`.
  2. `지금 실행` 토글 ON.
  3. 앱/서비스 상태 페이지 열기.
- 기대 결과:
  1. 10초 내 서비스 상태가 `running` 전이.
  2. `/api/v1/status` 요청이 200.

## 4) 실행/서비스 제어 (P0, W)

### TC-RUN-001 [P][UI]
- 제목: 서비스 시작
- 사전 조건: 설치 완료, 기본 포트 가용
- 버튼: `시작`
- 절차:
  1. 대시보드에서 `시작`.
  2. 진행 표시가 `시작 중`으로 전환되는지 확인.
- 기대 결과:
  1. 15초 이내 상태 `Running`.
  2. 노드 정보 API 응답 `is_running=true`.

### TC-RUN-002 [P][UI]
- 제목: 이미 실행 중인데 시작 버튼 다시 클릭
- 사전 조건: 현재 Running 상태
- 버튼: `시작`
- 절차:
  1. `시작` 재클릭.
- 기대 결과:
  1. 버튼이 `요청 무시`가 아닌 안전한 `이미 실행 중` 메시지를 반환.
  2. 중복 기동 프로세스 생성 없음.

### TC-RUN-003 [P][UI]
- 제목: 정상 중지
- 사전 조건: Running 상태
- 버튼: `중지`
- 절차:
  1. `중지` 클릭.
  2. Graceful timeout(예: 5초) 이내 종료 지연이면 진행 상태 확인.
- 기대 결과:
  1. 최종 상태 `Stopped`.
  2. 포트 바인딩 해제.

### TC-RUN-004 [P][UI]
- 제목: 중지 중 재시작 버튼 동시 클릭
- 사전 조건: Running 상태
- 버튼: `중지` + `재시작` 연속 클릭
- 절차:
  1. `중지` 클릭 후 즉시 `재시작`.
- 기대 결과:
  1. 상태 큐 직렬화( race 없음 ).
  2. 최종 30초 내 Running 복귀.

### TC-RUN-005 [W][CLI]
- 제목: CLI로 재시작
- 사전 조건: 데몬 설치 상태
- 명령: `eastseactl restart`
- 기대 결과:
  1. 표준 출력에 단계 로그(starting/stopping) 출력.
  2. 종료코드 0.

## 5) 업데이트/롤백 (P0/P1)

### TC-UPDATE-001 [P][UI]
- 제목: 업데이트 확인
- 사전 조건: 네트워크 연결
- 버튼: `업데이트 확인`
- 절차:
  1. 대시보드에서 버튼 클릭.
  2. `현재 버전/최신 버전` 텍스트 노출 확인.
- 기대 결과:
  1. 업데이트 없는 경우 `최신 버전입니다`.
  2. 업데이트 있는 경우 리스크 라벨/릴리즈 노트 제공.

### TC-UPDATE-002 [P][UI]
- 제목: 업데이트 다운로드 + 적용
- 사전 조건: 업데이트 사용 가능
- 버튼: `지금 업데이트`
- 절차:
  1. 알림에서 `지금 업데이트`.
  2. 해시 검증 완료 알림 대기.
  3. 자동 재시작 여부 확인.
- 기대 결과:
  1. checksum mismatch 없음.
  2. 버전이 일관되게 갱신.

### TC-UPDATE-003 [P][UI]
- 제목: 업데이트 실패 후 롤백
- 사전 조건: 업데이트 적용 중단 시뮬레이션
- 버튼: `업데이트 실패 시 복구`, `롤백`
- 절차:
  1. 의도적 네트워크 단절 후 업데이트 시도.
  2. 에러 페이지에서 `롤백`.
- 기대 결과:
  1. 이전 실행 버전으로 자동 복귀.
  2. 운영 데이터가 유지됨.

### TC-UPDATE-004 [W][UI]
- 제목: 수동 업데이트 체크(오프라인)
- 사전 조건: 네트워크 단절
- 버튼: `업데이트 확인`
- 절차: 클릭.
- 기대 결과: 오류 코드 표준 표시 + 재시도 가이드.

## 6) 네트워크/노드 상태 버튼 (P1)

### TC-NODE-001 [W][UI]
- 제목: 상태 새로고침
- 버튼: `상태 새로고침`
- 절차:
  1. 피어 수, 블록 높이, 연결 상태 영역 확인.
  2. 버튼 클릭 2회 연속.
- 기대 결과:
  1. 첫 조회/두 번째 조회 모두 값 동기화.
  2. 캐시 스탬프가 시간순 표시.

### TC-NODE-002 [W][UI]
- 제목: 피어 수강제확장
- 버튼: `피어 추가`
- 절차:
  1. `피어 추가` 입력창에 유효/무효 노드 주소 각각 1회.
- 기대 결과:
  1. 유효 입력은 연결 시도.
  2. 무효 입력은 구체적 오류.

### TC-NODE-003 [W][UI]
- 제목: 로그 보기
- 버튼: `로그 보기`, `로그 레벨: DEBUG`
- 절차:
  1. `로그 보기` 클릭.
  2. 레벨 토글.
- 기대 결과:
  1. 최근 로그 200줄 표시.
  2. 레벨 변경 즉시 반영.

## 12) 추가 CLI 전용 케이스 (요건 보강)

### TC-INSTALL-006 [P][CLI]
- 제목: Linux CLI 설치 스크립트 실행
- 사전 조건: root/non-root 모드 각각 테스트 환경 준비
- 명령: `curl -fsSL <install.sh> | sh -s -- --help` 또는 실제 설치 플래그
- 절차:
  1. 도움말/버전 플래그로 설치 동작 모드 점검.
  2. 실제 설치 플래그 실행.
  3. 설치 후 기본 경로/서비스 기동 상태 확인.
- 기대 결과:
  1. 설치 스크립트가 OS 탐지값을 정확히 판별.
  2. root권한 필요 동선이 있는 경우 명확한 안내 출력.
  3. 실행 후 바로 서비스 상태 조회 가능.

### TC-UPDATE-005 [W][CLI]
- 제목: 배포 전략 기반 배포 전환
- 사전 조건: 수동 업데이트 모드 허용
- 명령: `eastseactl deploy --strategy <blue-green|canary>`
- 절차:
  1. 현재 버전과 목표 버전을 지정해 배포 수행.
  2. 완료 후 전환/롤백 경로 확인.
- 기대 결과:
  1. 지정 전략 기반 스테이징/전환 로그 존재.
  2. 실패 시 즉시 롤백 경로 실행 또는 가이드 표시.

### TC-CI-001 [W][CLI]
- 제목: 릴리즈 파이프라인 게이트 검증
- 사전 조건: CI 실행 권한 및 아티팩트 저장 경로 존재
- 동작:
  - 패키징 단계 실행
  - 설치형 smoke(start→status→stop) 실행
  - 보안 스캔/체크섬 검증
- 절차:
  1. CI 구성에서 필수 게이트가 모두 실행되는지 조회.
  2. 게이트 1개라도 실패 시 파이프라인이 중단되는지 확인.
- 기대 결과:
  1. `REQ-050` 대상 게이트가 P0 기준으로 실패 없이 완료.
  2. 플랫폼별 아티팩트 경로/해시 검증 로그가 남음.

### TC-DOC-001 [W][DOC]
- 제목: 문서-API 계약 동기화
- 사전 조건: `docs/API.md`와 API 스키마 정의 파일 존재

  2. 누락/오래된 설명 비교.
